# Local and private demonstration setup
No live credentials are included. Create a dedicated Neon database using the free plan, then configure DATABASE_URL (pooled) and DATABASE_URL_UNPOOLED privately. Do not reuse an unrelated production DB.
Run npm ci, npm run db:migrate, privately set BOOTSTRAP_OWNER_EMAIL and BOOTSTRAP_OWNER_PASSWORD, npm run db:seed, npm run db:seed-menu. Remove bootstrap credentials afterward. Seed refuses to overwrite existing accounts.
The shared fictional order tenant is OFF by default (ENABLE_DEMO_ORDERS=0). Enable only for a private test database. For invite-only isolated demos use ENABLE_ISOLATED_DEMO=1 and a randomly generated 24+ character DEMO_ACCESS_CODE in server environment. Do not expose it in source, logs or public URLs. Set canonical APP_URL to exact HTTPS origin for production.
Isolated demos are valid for two hours. Their staff identities cannot sign in with ordinary credentials; roles are confined to their own tenant. End session revokes access and tracking/table tokens. No records are destroyed automatically. Provisioning limited to 20 active and 200 retained demos; cleanup requires explicit operator review. Each isolated demo capped at 100 orders and 100 combined booking requests. Never enable public demo access before CI and security review.
No real payment, tax invoice, delivery or external AI integration. All payments are fictional manual records.
